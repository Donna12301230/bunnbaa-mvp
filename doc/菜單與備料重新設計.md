- 只有白飯有接到半成品
- 組合預覽只到 `白飯 一碗 + 豬肉 + 茄子 + 苦瓜 + 辣炒年糕 → 自選便當・NT$ 60`，沒有材料

- 備料組成：蛋餅皮 ×1、煎蛋 ×2、起司片 ×1，**半成品都接了，但成本還是 NT$0.0**——原因是半成品裡沒有原物料、或原物料沒填單價，畫面沒有說

2. 成本算不出來時，直接寫出**原因**，並可以點過去補（3.2(c)）
3. 材料用合成格子顯示**現有／需要**（3.2(b)）

## 2. 設計原則

1. **一條主線，每頁都看得到前後。** 任何一頁都能看到資料從哪裡來、會影響哪裡，而且點得過去。
2. **照使用頻率排。** 每天會用的放最上面，設定一次就好的放下面。
3. **不用離開目前的頁面。** 缺什麼就在原地補，不用關視窗換頁。
4. **哪裡缺資料直接標出來。** 會讓成本、備料、叫貨算錯的空欄位要標示，不要默默當成 0。

```
原物料 ──▶ 半成品(配方) ──▶ 菜單品項 ──▶ 訂單
                                          ├─▶ 每日備料（每天）
                                          └─▶ 採購叫貨（每週）
```

## 3. 新設計

### 3.1 選單重排、加設定進度條

**選單順序**（`VendorPortalLayout.tsx`）：

| 新順序 | 頁面 | 使用頻率 |
|---|---|---|
| 1 | 今日備料（原「每日備料」） | 每天 |
| 2 | 採購叫貨 | 每週 |
| 3 | 菜單管理 | 換菜時 |
| 4 | 配方原物料 | 開店時、漲價時 |

**設定進度條**：四頁上方共用一條小元件，例如：

```
原物料 ✓ → 配方 ✓ → 菜單 ⚠2 → 本週盤點 ✗ → 叫貨單 →
```

- 每一格點下去都跳到要補的地方（例如 ⚠2 → 菜單管理，並捲到那兩個品項）
- 新店家照著點完就能開賣；資料都設好以後可以收起來，只剩一行提示
- 判斷規則（前端計算，資料來自 `useVendorCatalog` 和菜單）：
  - 原物料：至少 1 筆，而且每一筆都有單價和供應商
  - 配方：每個半成品至少有 1 種原物料
  - 菜單：每個上架品項的主菜、配菜、白飯、固定附餐都接了半成品
  - 盤點：本週的 `inventory/{週一}` 已經有 `counted: true`
  - 叫貨單：下週的 `purchaseLists/weekly_{週一}` 已經存在

### 3.2 菜單管理

**(a) 菜名和半成品合成一個欄位（截圖 2）**

現在每一列是「照片｜菜名輸入框｜半成品下拉｜價格」，改成「照片｜**菜色欄位**｜價格」：

```
[照片] [ 茄子                ▾ ] [ 50 ]
        ┌───────────────────────┐
        │ 魚香茄子    已有配方   │  ← 打字即搜尋既有半成品
        │ 涼拌茄子    已有配方   │
        │ ＋ 建立「茄子」         │  ← 找不到就直接建
        └───────────────────────┘
```

- 打字會搜尋既有的半成品；選了就同時決定菜名和半成品
- 找不到就選「＋ 建立『茄子』」：在原本的視窗上疊開半成品表單（從 `VendorPortalRecipes.tsx` 抽成共用元件），名稱帶入、存檔後自動選好，菜單視窗裡剛填的內容都保留
- 不想現在填配方，可以先「只建名稱」：半成品先存起來、標成「待補配方」，之後在配方頁或進度條補
- 顯示給消費者的菜名預設等於半成品名；需要不同名稱（例如半成品叫「滷雞腿」、菜單上寫「招牌雞腿」）時，展開「顯示名稱」另外填
- 適用於主菜、配菜預設菜、候選菜、單品的備料組成；白飯維持下拉即可

**(b) 組合預覽加材料總和——合成格子（docx 第 4 列＋附圖）**

照目前下拉選的組合（白飯份量、主菜、配菜、自訂欄位）即時算出，用合成格子顯示：

```
份數：[ 1 份 ▾ ]   （可切到「明天已訂 42 份」）

 ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐          ┌────────┐
 │ 白米 │ + │雞腿肉│ + │ 茄子 │ + │ 苦瓜 │ + │ 年糕 │   ──▶    │雞肉便當│
 │ 75g  │   │ 139g │   │ 88g  │   │ 84g  │   │ 60g  │          │ NT$ 90 │
 └──────┘   └──────┘   └──────┘   └──────┘   └──────┘          └────────┘
 (5kg/75g)  (0/139g)   (2kg/88g)  (1kg/84g)  (3kg/60g)
             ▲ 紅色：庫存不夠

成本 NT$ 38 ｜ 售價 NT$ 90 ｜ 毛利 58%      ＋調味、包材 4 項（展開）
```

- 每格是一種**原物料**（生料用量），格子下面是**（現有庫存／需要）**；不夠的格子變紅
- 「現有」取本週盤點 `inventory/{週一}`，沒盤點時用叫貨單的理論庫存，並標「理論值」
- 份數可以切換：1 份（看配方）、或某天已訂份數（看夠不夠做）
- 生料用量用現有的 `rawAmount()`（熟重 ÷（熟成率 ×（1 − 損耗率）））
- 半份候選菜要乘 `portion_level`；白飯「半碗、一碗半」要乘相對應的比例，規則和 `functions/src/bento.js` 的 `componentPortions` 一致
- 調味料、包材預設收合，避免格子太多（和 `portionTextFor` 的 `PORTION_SKIP_CATEGORIES` 同一套分類）
- 毛利低於門檻（例如 40%）時改成橘色提示
- 單品（截圖 3）也一樣：`蛋餅皮 + 煎蛋 ×2 + 起司片 → 起司蛋餅`，下面展開成麵粉、雞蛋、起司片…

**(c) 成本算不出來時寫原因（截圖 2、3）**

`成本 0.0` 改成直接說缺什麼，點了就去補：

| 狀況 | 顯示 | 點了 |
|---|---|---|
| 沒接半成品 | `⚠ 未接配方` | 打開 (a) 的建立視窗 |
| 半成品沒有原物料 | `⚠ 配方沒有原物料` | 疊開該半成品的配方編輯 |
| 原物料沒單價 | `⚠ 雞蛋 未填單價` | 疊開該原物料編輯 |
| 都有 | `成本 NT$ 12.5` | — |

**(d) 品項卡片標示配方缺漏**
- 卡片上顯示「⚠ 配菜 2 未接配方」「⚠ 成本不完整」之類的標籤，點了直接打開編輯視窗

### 3.3 配方原物料

**(a) 半成品顯示「用在哪些菜」**
- 每張半成品卡片下面顯示「用在：雞腿便當、排骨便當」，點了跳到菜單管理並打開該品項
- 刪除時的確認視窗寫出「有 N 道菜用到這個半成品，刪除後這些菜的備料會少算」
- 沒有任何菜用到的半成品顯示灰色「未使用」

**(b) 原物料待補標記**
- 標籤：`未填單價`、`未選供應商`、`沒有配方用到`
- 分頁標題直接顯示數量，例如「原物料（⚠3）」
- 列表上方加篩選：全部／待補

**(c) 漲價影響**（之後再做）
- 改單價後提示「這會影響 5 道菜的毛利」，並列出新的毛利

### 3.4 採購叫貨

**(a) 盤點併進叫貨單**
- 叫貨單的「庫存」欄直接可以改（預設是理論庫存）；改完存進 `inventory/{週一}`，並自動重新產生叫貨單
- 原本的「盤點」分頁拿掉；標題旁邊顯示「本週已盤點 ✓」或「未盤點，用理論庫存計算」

**(b) 需求來源展開**
- 每一列可以展開，看「這週為什麼要這麼多」：

```
雞腿肉  需要 18.2 kg
  ├ 雞腿便當   120 份（已確定 80 ＋ 預測 40）
  └ 三寶飯      30 份
```

- 需要在 `functions/src/purchasing.js` 產生叫貨單時，多存每項原物料的 `sources: [{ menu_item_id, name, portions }]`

**(c) 臨時補貨區**
- 每日備料算出的缺料（`prepPlans.shortages`）會出現在叫貨頁最上方的「臨時補貨」卡片
- 跟週叫貨單共用同一套 LINE 文字產生（`shareLine`），依供應商分組
- 缺料用 3.2(b) 的合成格子呈現（現有／需要，紅色＝不夠），跟菜單、備料看到的是同一個畫面

### 3.5 今日備料

**(a) 領料單**
- 把 `prepPlans.raw_needs` 顯示成「今天從冰箱拿出：雞腿 120 支、高麗菜 9.6 kg…」
- 依原物料類別分組（肉、葉菜、乾貨…），可以勾選、可以列印（和出餐標籤分開印）
- 畫面上用 3.2(b) 的合成格子：每格一種原物料，下面寫（現有／今天需要），不夠的變紅並直接接 (c) 的叫貨按鈕；也可以切到每道半成品看 `半成品 ← 原物料` 的合成圖

**(b) 半成品任務展開配方**
- 點半成品任務會展開：配方原物料 × 今天的份數、每批幾份、要幾批、用什麼設備

**(c) 缺料一鍵叫貨**
- 缺料警示卡片加「LINE 叫貨」按鈕（共用 3.4(c) 的文字產生）

**(d) 截單前先估算**
- 還沒截單時，用目前的訂單在前端先算半成品份數和原物料需求，標示為「目前預估，截單後可能變動」
- 計算邏輯要和後端 `componentPortions`／`rawNeeds` 一致；建議抽成前後端共用的規則，或至少在兩邊加註互相對照
